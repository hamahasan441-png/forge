- v20 HARDENING (defense in depth, all verified by tests):
  * shellguard: structural command parsing (quote-aware split/tokenize) +
    path-aware risk classification — block/danger/confirm/low/safe. Catastrophic
    commands (rm -rf /, mkfs, dd to raw devices, fork bombs, shutdown, redirects
    over /etc/passwd, find / -delete) ALWAYS refused; destructive-outside-project
    refused for the model; risky commands ask y/N on a TTY (FORGE_ASSUME_YES=1
    or tools.assumeYes when piped); sudo needs tools.allowSudo
  * safePath: writes confined to the project dir (../, absolute, and SYMLINK
    escapes caught via realpath of nearest existing ancestor); reads outside
    allowed except sensitive files (.env, .ssh, keys, credentials, forge config)
    checked on logical AND real path; ~ expanded like a shell
  * SSRF (netguard): fetch_url resolves DNS and validates EVERY address —
    loopback, 0/8, 10/8, CGNAT 100.64/10, 172.16/12, 192.168/16, link-local +
    cloud metadata, IPv6 ::1/fc00::/7/fe80::/10/IPv4-mapped; DNS-rebinding safe
    (all resolved records must pass); tools.fetchPrivateUrls /
    FORGE_ALLOW_PRIVATE_URLS=1 opt-in for local stacks
  * secrets: every tool RESULT, memory write, and terminal note is redacted
    (sk-*, AKIA*, ghp_*, xox*, AIza*, JWTs, private keys, KEY=value shapes);
    display stays raw for the user, the model + sessions never see raw secrets
  * skills: name validation (plain dir names only) + realpath containment —
    ../../ traversal impossible; skills-dir resolution order fixed
